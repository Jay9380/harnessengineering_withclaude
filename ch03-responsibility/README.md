# 3장 · 에이전트·스킬·오케스트레이터의 책임 분리 — '어디에 두느냐'는 비용 문제다

책 3장의 질문은 "이 내용은 누구(에이전트)의 것인가, 어떻게(스킬)의 것인가, 언제·누구와(오케스트레이터)의 것인가"다.
클로드 코드에서 이 구분은 **언제 무엇이 컨텍스트에 올라오는가**로 드러난다. 이 폴더는 그것을 숫자로 잰다.

## 실험: 같은 300줄을 세 곳에 넣어 보기

300줄짜리 커밋 규칙(약 2만 토큰)을 ① `CLAUDE.md` ② 에이전트 본문 ③ 스킬 본문에 각각 넣고,
메인 세션이 모델을 한 번 부를 때 **읽은 입력 토큰**(input + cache_creation + cache_read)을 비교한다.

```bash
cd ch03-responsibility/experiments && ./context_cost.sh     # haiku 8회, 약 $0.1
```

### 읽는 법

- **CLAUDE.md는 상시 비용이다.** 쓰든 안 쓰든 매 호출, 그리고 모든 서브에이전트가 읽는다. 그래서 책(10장)이 CLAUDE.md를 '포인터'로 쓰라고 한다.
- **에이전트·스킬은 시작할 때 이름+description만 낸다.** 본문 300줄이나 1줄이나 차이가 없다 — 절차를 늘려도 평소 비용은 그대로다.
- **둘의 차이는 호출할 때 나온다.**
  - 스킬 본문은 **호출한 대화(메인)에 들어온다** — 격리되지 않는다. 이후 턴에서도 남는다.
  - 에이전트 본문은 **서브에이전트의 별도 컨텍스트**에만 올라가고, 메인에는 결과 몇백 토큰만 돌아온다.
- 그래서 책의 구분이 비용으로도 맞다: **절차**(여러 곳에서 쓰는 '어떻게')는 스킬로, **독립된 관점**(검증자처럼 메인과 섞이면 안 되는 '누가')은 에이전트로,
  **매번 필요한 아주 짧은 규칙과 포인터**만 CLAUDE.md로.

## 측정하다 걸린 함정 — 계정 커넥터가 숫자를 흔든다

처음 측정에서는 "스킬을 두기만 해도 +1,963토큰"이 나왔다. 원인은 스킬이 아니었다.
init 이벤트의 도구 수가 실행마다 29 / 48 / 95로 달랐고, 계정에 연결된 claude.ai 커넥터(MCP)가 어떤 실행에서는 `pending`, 어떤 실행에서는 `connected`였다.
`--setting-sources project`만으로는 이것이 빠지지 않는다. 스크립트는 다음 두 가지로 고정한다.

```bash
export ENABLE_CLAUDEAI_MCP_SERVERS=false   # claude.ai 커넥터 끄기
claude -p ... --strict-mcp-config          # --mcp-config 로 준 것 외의 MCP 무시
```

> 하네스를 측정할 때는 **측정 환경 자체가 하네스의 일부**다. 비교 실험 전에 init의 `tools`·`mcp_servers`가 조건마다 같은지 먼저 확인한다.

## 책의 안티패턴 4종과 이 실험의 관계

| 안티패턴 (책 pp.65–67) | 이 실험에서 보이는 비용 |
|---|---|
| 1. 에이전트 하나가 모든 역할 | 검증까지 한 컨텍스트에서 → 1장의 자기 검증 실패 + 최소 권한 붕괴 |
| 2. 스킬이 팀 전체를 지휘 | 지휘 로직 전체가 호출 시 메인 대화에 합류 (+본문 전부) |
| 3. 리더가 직접 일함 | 서브에이전트의 '결과만 반환' 이점을 버리고 메인 컨텍스트가 참 |
| 4. 에이전트 파일에 절차 내장 | 비용은 그 에이전트 안에 갇히지만, 다른 에이전트가 쓰려면 복사 → 기준이 갈라짐 |
