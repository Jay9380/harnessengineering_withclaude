# 13장 · 레거시 마이그레이션 팀 — 작업 큐에서 '가져가기'를 누가 책임지나

책 13장은 수백~수천 파일 마이그레이션을 **감독자 패턴**으로 푼다. dependency-mapper가 `batches.json`(작업 단위 상태 머신: pending → in-progress → done / manual-queue)을 만들고,
incremental-migrator 워커 여럿이 남은 배치를 **스스로 가져간다(claim)** — 리눅스 커널의 work-stealing 스케줄러처럼. 감독자는 '분배자'로만 남는다.
이 폴더는 그 핵심 동작, **여러 워커가 같은 큐에서 동시에 가져가기**를 실제로 돌린다.

```bash
cd ch13-migration/experiments
./run.sh all          # (A)·(B) 각 1회, haiku 워커 3개씩 (약 $0.6)
REP=3 ./run.sh A      # 회차를 바꿔 로그 보존
```

## 설정

- `batches.json`에 배치 8개. `b-005`는 `b-001`에, `b-008`은 `b-005`에 의존.
- 배치 '변환'은 `./work.sh <배치> <워커>` — 1~3초 뒤 `work.log`에 한 줄. 중복·누락·순서 위반을 이 로그로 센다.
- 워커 3개(`claude -p`, haiku)를 **동시에** 띄운다.
  - **(A) 직접 편집**: 워커가 `batches.json`을 Read/Edit해 선점(in-progress, owner)하고, 끝나면 done으로 고친다.
  - **(B) 원자적 claim**: 워커는 `./claim.sh <워커>`(mkdir 잠금 + 의존성 검사)로 받고 `./claim.sh --done <배치>`로 끝낸다. JSON은 직접 고치지 않는다.

## 결과 (2026-10-02)

| | 회차 | 처리 | 중복 | 누락 | 의존 순서 위반 | 최종 상태 |
|---|---|---|---|---|---|---|
| (A) 직접 편집 | 5회 | 8, 8, 8, **7**, **7** | 0 | **2회 — b-006** | 0 | 그 2회는 `in-progress` 1개가 영원히 남음 |
| (B) 원자적 claim | 2회 | 8, 8 | 0 | 0 | 0 | 모두 done |

### (A)의 누락은 경합이 아니라 '버려진 선점'이었다

5회차 로그(`runs/A-5-*`):

```text
batches.json:  {"id": "b-006", "status": "in-progress", "owner": "w3"}
work.log:      b-001 w2 … b-008 w2   (7줄 전부 w2)
w1: "I need approval to run the worker loop that will claim and process batches …"   ← 자기만의 루프 스크립트를 짜려다 승인 대기로 멈춤
w3: "b-006 배치를 in-progress 상태로 선점 … ❌ ./work.sh b-006 w3 실행에 권한 필요"   ← 실행 형태가 허용 패턴과 달라 거부 → 선점한 채로 종료
```

- **중복 처리는 한 번도 없었다.** 잠금 없이도 LLM 워커는 느려서(한 번 읽고 고치는 데 수 초) 이번 규모에서는 경합이 드러나지 않았다.
- 실제 실패 모드는 **"가져가 놓고 끝내지 못한 워커"**다. 워커가 막히면 배치는 `in-progress`로 남고, 다른 워커는 그것을 남의 일로 보고 건드리지 않는다 → 아무도 하지 않는 일이 생긴다.
- 그리고 **일이 한 워커에 쏠렸다**(w2가 7/7). 나머지 둘은 즉흥적으로 다른 방법(루프 스크립트 작성, 다른 실행 형태)을 시도하다 권한에 막혔다. 병렬 3명이 사실상 1명이었다.
- (B)는 워커가 할 수 있는 일을 `claim.sh`·`work.sh` 두 명령으로 좁혔고, 선점·의존성 판단을 코드가 했다 → 매번 8/8.

### 책에 더할 것 — 선점에는 만료가 필요하다

책의 상태 머신은 pending → in-progress → done / manual-queue다. 위 결과는 **in-progress에 시간 제한(리스)**이 필요하다는 것을 보여 준다:
`claimed_at`을 기록하고, N분 안에 done이 안 되면 감독자가 pending으로 되돌리거나 manual-queue로 보낸다.
책이 감독자에게 맡긴 세 게이트(예산·실패율·회귀)에 **'방치된 선점'**을 하나 더 두는 셈이다.

### 측정 함정

첫 실행에서는 `echo "<배치> <워커>" >> work.log`로 기록하게 했는데, **작업 폴더로의 리다이렉트는 승인 대상**이라 두 조건 모두 거부됐다(2·9장 실습과 같은 현상). 기록을 `./work.sh`로 옮겨 다시 돌렸다.
