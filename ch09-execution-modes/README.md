# 9장 · 팀/서브에이전트/하이브리드 — 병렬은 모드가 아니라 호출 방식, 의존성은 명시해야 한다

책 9장은 실행 모드(에이전트 팀·서브에이전트·하이브리드)를 고르는 기준이 "몇 명이냐"가 아니라 **"동시에 소통해야 하느냐"**라고 한다.
그리고 두 가지를 경고한다 — "서브에이전트 = 순차"는 오해다(`run_in_background=true`면 병렬), 그리고 **암묵적 의존성**(서브끼리 통신하지 않는다면서 한 서브의 출력이 다른 서브의 입력으로 쓰이는 경우)이다.
둘 다 재 본다.

```bash
cd ch09-execution-modes/experiments
./run.sh 1      # 병렬 vs 순차 (haiku, 약 $0.12)
./run.sh 2      # 암묵적 의존성 (haiku, 약 $0.12)
```

> 6장에서 본 대로 Claude Code 2.1.286에는 TeamCreate가 없으므로, 여기서 '모드'는 서브에이전트를 **어떻게 호출하느냐**(백그라운드 병렬 / 순차)의 차이다.

## 실험 1 — 서브에이전트는 순차인가

`sleeper` 에이전트(Bash로 `sleep 15` 후 번호를 답함) 3개를 같은 일로 띄웠다.

| 호출 방식 | 메인의 호출 | 벽시계 |
|---|---|---|
| 한 응답에서 3개를 `run_in_background: true` | Agent ×3 (한 번에) | **29초** |
| 하나씩, 앞이 끝난 뒤 다음 (`run_in_background: false`) | Agent ×3 (차례로) | **68초** |

**병렬은 모드가 아니라 호출 방식이다.** 서브에이전트도 한 응답에서 백그라운드로 여러 개를 띄우면 동시에 돈다(15초 ×3 → 약 29초, 오버헤드 포함).
팀과 서브에이전트의 차이는 '병렬 여부'가 아니라 **'서로 말할 수 있느냐'**다(책 p.181, 6장 실습).

## 실험 2 — 암묵적 의존성: 동시에 띄우면 데이터가 있어도 답이 틀린다

`producer`는 20초 기다린 뒤 비밀값을 `_workspace/a.txt`에 쓴다. `consumer`는 그 파일을 읽어 값을 보고한다(Read만 가짐).

| 띄우는 방식 | 결과 |
|---|---|
| 둘을 한 응답에서 동시에 백그라운드로 | consumer가 먼저 끝나 **"파일을 찾을 수 없습니다"** → 메인은 그대로 전달. 최종 답에 값 **없음** |
| producer가 끝난 뒤 consumer | 최종 답 `V-6929-5319` — **정확** |

동시 실행의 최종 답 흐름:

```text
"producer와 consumer 에이전트를 동시에 백그라운드에서 띄웠습니다."
"consumer 에이전트가 완료되었는데 파일을 찾을 수 없다고 보고했습니다. producer가 아직 작업 중이므로 완료될 때까지 기다리겠습니다."
"둘 다 완료되었습니다. Consumer가 보고한 값: 죄송하지만, _workspace/a.txt 파일을 찾을 수 없습니다 …"
```

- 메인은 **producer가 아직 일하는 중이라는 것을 알고 있었고**, producer가 끝난 시점에는 파일이 실제로 존재했다. 그런데 consumer를 다시 돌리지 않고 낡은 결과를 전했다.
  지시("consumer가 보고한 값을 그대로 전해 줘")를 글자 그대로 따른 것이다 — 의존성을 아는 것과 의존성을 **처리하는 것**은 다르다.
- consumer는 빈 결과를 지어내지 않고 "파일 없음"을 정직하게 보고했다. 책의 "말없이 빈 결과를 받아 진행"보다는 나은 모양이지만, **전체 결과가 틀렸다는 점은 같다.**
- 해법은 책 그대로: 의존성을 명시하고(오케스트레이터가 앞 서브의 완료를 확인한 뒤 다음 서브를 호출), 이 순간 '순수 서브에이전트 모드'는 하이브리드(단계가 있는 오케스트레이션)가 된다. 작업 큐를 쓴다면 `TaskUpdate addBlockedBy`(6장 실습).

### 처음 설계가 무효였던 이유

첫 실행에서는 producer가 `sleep 20 && mkdir -p _workspace && cat secret.txt > _workspace/a.txt` 한 줄을 Bash로 실행하게 했는데,
`Bash(sleep *)` 허용만으로는 **복합 명령의 나머지 부분(mkdir, 리다이렉트)이 승인 대상**이라 거부됐다(2장 실습의 '덤'과 같은 현상).
producer가 Read·Write 도구로 파일을 쓰도록 바꿔 다시 돌렸다.
