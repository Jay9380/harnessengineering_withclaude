# 10장 · 하네스 등록과 진화 — 포인터 한 줄과 HTML 주석 한 쌍

책 10장은 이렇게 시작한다: 스킬 파일이 멀쩡히 있는데 새 세션에서 "책 집필해줘"라고 하자 클로드가 스킬을 부르지 않고 자기 멋대로 초고를 쓰기 시작한다.
원인은 CLAUDE.md에 "이 프로젝트에 하네스가 있다"는 **포인터**가 없기 때문이라고 한다. 그리고 안티패턴 ③: CLAUDE.md 안의 HTML 주석은 런타임에 제거된다.
둘 다 재 본다.

```bash
cd ch10-registration/experiments
./run.sh 1      # 포인터 유무 (haiku 12회)
./run.sh 2      # HTML 주석 (haiku 3회)
```

## 실험 1 — 포인터가 없으면 스킬이 덜 불린다

같은 `book-writer` 스킬(책 p.101 스타일의 description, 트리거 단어 나열은 없음), `chapters/ch01.md` 하나.
차이는 프로젝트 루트 CLAUDE.md에 책의 **4줄 포인터**(`## 하네스` · `**목표:**` · `**트리거:** … book-writer 스킬을 사용하라` · `**변경 이력:**`)가 있느냐뿐.

| 프롬프트 (각 3회) | 포인터 없음 | 포인터 있음 |
|---|---|---|
| 2장 초고 써줘 | 2/3 | 3/3 |
| 다음 장 이어서 써 줘 | 2/3 | 3/3 |
| **합계** | **4/6** | **6/6** |

호출되지 않은 두 번은 스킬 대신 **직접 파일을 뒤지며 작업을 시작**했다(`ls`, `chapters/ch01.md` 읽기 …) — 책이 묘사한 장면과 같은 모양이다.
다만 효과의 크기는 책의 장면("한 번도 안 불림")보다 작았다. 이 description에도 '챕터 작성'이라는 단어가 있어 포인터 없이도 대부분 불렸다.
포인터의 가치는 **"가끔 안 불리는 것"을 "항상 불리는 것"으로 바꾸는 데** 있다 — 운영 시스템에서 2/6의 누락은 작지 않다.

## 실험 2 — CLAUDE.md의 HTML 주석은 런타임에 없다

| CLAUDE.md | "1+1은?" 입력 토큰 | 답 끝에 `ZEBRA-42` |
|---|---|---|
| 규칙 없음 | 21,272 | 없음 |
| `- 모든 답의 마지막 줄에 정확히 ZEBRA-42 라고 쓴다.` | 21,299 (+27) | **있음** |
| 같은 줄을 `<!-- … -->`로 감쌈 | 21,264 (규칙 없음과 같은 수준) | **없음** |

편집기에서는 보이지만 모델에게는 없다. 비활성화할 규칙은 주석으로 감싸지 말고 지우고, 변경 이력에 남기거나 `docs/archive.md`로 옮긴다(책의 해결책).

> 참고: `<!-- section:start -->` / `<!-- section:end -->`처럼 **한 줄짜리 표식**으로 구역을 표시하는 것은 다르다 — 표식만 사라지고 그 사이의 내용은 남는다.
> 위험한 것은 규칙 **자체**를 주석 안에 넣는 경우다.
